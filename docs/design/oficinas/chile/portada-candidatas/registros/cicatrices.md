# Cicatrices

Lo que falló o costó tiempo, con fecha, causa y **en qué se convirtió**. Es el método de MAGIA: «cada regla nació de una cicatriz real».
Un incidente real se convierte en una de cuatro cosas:
- **Puerta (gate):** una comprobación objetiva que se puede hacer con un comando o un dato (tamaño, licencia, código de respuesta).
- **Juez:** una revisión subjetiva hecha por alguien que no escribió el trabajo (el agente `juez-foto-portada`).
- **Plantilla:** un formato fijo que evita el error.
- **Punto de control humano:** una decisión que solo el dueño puede tomar.
O, si no cabe en ninguna, una **regla** nueva en `SKILL.md`.

**Reglas de este archivo**
- Nada se borra. Si una cicatriz se supera, cambia a `estado: superada` con fecha y nota. Una API o un banco que no sirve **no se quita en silencio**: se documenta por qué.
- Solo la sesión principal escribe aquí. Los agentes proponen en «incidencias».
- Si una cosa pasó dos veces, es candidata a regla o puerta.

## Plantilla para una cicatriz nueva
`| C-NN | AAAA-MM-DD | <qué pasó, en una frase> | <causa, si se sabe; si no, «sin confirmar»> | <puerta | juez | plantilla | punto de control | regla> + dónde queda | <vigente | por probar | por confirmar | superada> |`
